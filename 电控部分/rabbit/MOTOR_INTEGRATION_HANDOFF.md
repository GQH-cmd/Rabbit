# Rabbit 电机集成交接说明

> 更新时间：2026-11-24。新对话开始处理电机前，先阅读本文件、`Codex.md`、`LIMIT_SWITCH_WIRING.md`，然后执行 `git status --short`。工程中存在尚未提交的有效改动，不要重置或覆盖。

## 1. 当前目标与边界

- MCU：STM32F407VET6，无 RTOS，使用 STM32 HAL 和 CMake。
- 电机1负责水平方向，电机2负责竖直方向。
- 电机不能通过 CAN 控制，计划改用串口通信，优先考虑 USART2。
- PA2/PA3 已为未来 USART2 预留，CAN1 已从 CubeMX、构建和运行配置中移除，PD0/PD1 已释放。
- 当前没有电机串口协议、波特率、地址、帧格式、停止确认或故障反馈定义。拿到驱动器完整文档前，不得猜测协议或发送真实电机命令。
- 泵驱动由其他对话处理。当前 Simulation 仅产生虚拟泵请求，不驱动真实电机或真实泵。

## 2. 两个业务流程

### FEED

1. 自检通过后，电机1向左运动。
2. 左开关有效后，立即停止电机1。
3. 电机2向下运动。
4. 左下开关有效后，立即停止电机2。
5. 奶泵工作2秒（当前为虚拟请求）。
6. 电机2向上运动。
7. 左上开关有效后，立即停止电机2并结束任务。

### CLEAN

1. 自检通过后，电机1向右运动。
2. 右开关有效后，立即停止电机1。
3. 电机2向下运动。
4. 右下开关有效后，立即停止电机2。
5. 清洗液泵工作3秒（当前为虚拟请求）。
6. 水泵工作5秒（当前为虚拟请求）。
7. 电机2向上运动。
8. 右上开关有效后，立即停止电机2并结束任务。

## 3. 六个常开位置开关

开关使用内部上拉，`COM` 接 GND，`NO` 接 GPIO；按下后软件值为1。软件消抖时间为20毫秒。

| 功能 | STM32 引脚 | 排针 | 位 | 掩码 |
|---|---|---|---:|---:|
| 左 | PE8 | J3-19 | 0 | `0x01` |
| 右 | PE9 | J3-18 | 1 | `0x02` |
| 左上 | PE10 | J3-17 | 2 | `0x04` |
| 左下 | PE11 | J3-16 | 3 | `0x08` |
| 右上 | PE12 | J3-15 | 4 | `0x10` |
| 右下 | PE13 | J3-14 | 5 | `0x20` |

实现文件：

- `BSP/Inc/limit_switches.h`
- `BSP/Src/limit_switches.c`
- `LIMIT_SWITCH_WIRING.md`

限位开关在真实机构到位后会持续保持按下。当前状态机判断的是消抖后的有效电平，不依赖“按下后松开”的边沿：目标开关持续有效时会停止对应电机并进入下一阶段。

## 4. 已完成的硬件验证

2026-11-24 已用实体开关验证 FEED 所需的三个输入：

- PE8 左：原始值和消抖值均为 `0x01`。
- PE11 左下：原始值和消抖值均为 `0x08`。
- PE10 左上：原始值和消抖值均为 `0x04`。
- PE8、PE10、PE11 同时接地时，原始值和消抖值均为 `0x0D`。

已烧录并校验 `build/Simulation/rabbit.elf`，通过 ESP32 COM11（115200 baud）完成端到端测试：

```text
PING  -> foc_pong
ARM   -> foc_accepted
FEED  -> foc_accepted
```

按左、左下、左上顺序触发后，FEED 自动返回：

```text
armed=1
state=IDLE
task=0
fault=0x00000000
```

测试结束后发送了 `STOP`，最终状态为：

```text
armed=0
state=IDLE
task=0
fault=0x00000000
```

该测试证明开关、SPI 指令链路和 Simulation 状态机可以配合工作；没有证明真实电机能够启动、停止或反馈状态。

## 5. 当前状态机接口

主要文件：

- `App/Inc/app.h`
- `App/Src/app.c`

`AppRuntime` 中与电机集成有关的诊断字段：

- `task_stage`
- `motor1_request`
- `motor2_request`
- `pump_request`
- `limit_switch_raw_mask`
- `limit_switch_mask`
- `stage_started_ms`

方向请求定义：

```text
APP_MOTOR_STOPPED
APP_MOTOR_MOVE_LEFT
APP_MOTOR_MOVE_RIGHT
APP_MOTOR_MOVE_UP
APP_MOTOR_MOVE_DOWN
```

Simulation 目前只更新这些请求，不驱动电机。Debug/生产语义仍拒绝 FEED 和 CLEAN，直到真实串口电机层完成。

每个等待限位阶段当前超时为30秒。任务停止后，Simulation 使用约300毫秒的虚拟停止稳定时间。

## 6. 电机集成建议

拿到电机驱动器通信文档后，先确认：

1. USART 外设、TX/RX 引脚、电平、波特率、数据位、校验位和停止位。
2. 两个电机是共用总线并带地址，还是使用两个独立串口。
3. 左、右、上、下对应的速度和方向编码。
4. 停止命令是自由停机、减速停机还是抱闸。
5. 是否有命令应答、运行状态、故障码和停止确认。
6. 通信丢失、驱动器离线和命令超时后的安全行为。

实现时建议分层：

```text
App 状态机
    -> MotorController（电机1/电机2、方向、停止确认、故障）
        -> UART 驱动与协议编解码
            -> STM32 HAL UART
```

状态机不应直接拼接串口字节。限位触发后先请求停止，并在驱动器确认停止后才开始另一轴运动或启动泵；如驱动器不提供反馈，应明确采用的保守等待时间和风险。

## 7. 接真实电机前必须补齐的安全项

当前 Simulation 仍有以下缺口，不能原样用于真实执行器：

1. 左和右同时有效、同一侧上和下同时有效等非法组合校验。
2. 目标限位在运动开始前已经有效时的处理。目前会立即判定该阶段到位。
3. 相反方向限位互锁，例如左限位有效时禁止继续向左。
4. 限位开关卡住、断线和始终不释放的诊断。常开开关断线会表现为“未按下”。
5. 每个轴分别配置的合理运动超时，不能仅依赖统一的30秒值。
6. 电机停止确认和停止失败故障。
7. 串口错误、应答超时、驱动器故障码和紧急 STOP 的最高优先级处理。
8. 上电或复位时的位置不确定性和回零策略。

在连接机械负载前，应先悬空或低速、低功率测试单个方向命令和 STOP；随后单轴测试限位，最后才执行完整 FEED/CLEAN。

## 9. 新对话开始时需要用户提供

- 电机完整型号。
- 驱动器完整型号。
- 串口协议说明书或清晰照片/PDF。
- 驱动器供电、电机供电和逻辑接口电平。
- 两个驱动器的实际接线方案。
- 期望速度、加减速、制动方式和允许的最大运行时间。

在这些信息齐全前，可以设计接口和测试桩，但不能安全地实现或实测真实电机命令。
